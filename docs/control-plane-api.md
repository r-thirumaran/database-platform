# Control Plane API (v1)

Base path: `/api/v1`. JSON everywhere. Timestamps are ISO-8601 UTC strings. Ids are opaque strings
(UUIDs generated by the control plane). Lists are returned as plain JSON arrays unless a `page`
parameter is given, in which case `{ "items": [...], "page": n, "size": n, "total": n }` is returned.

Errors: `{ "status": 404, "error": "NOT_FOUND", "message": "...", "path": "/api/v1/..." }`.

Two kinds of callers:

* **Operators / UI** — public endpoints below. Protected by the configured security mode
  (`DBP_SECURITY_MODE=none|basic`, default `none` for the POC).
* **Platform components** (gateway, proxy) — `/api/v1/internal/**`, protected by a shared service
  token sent as `X-DBP-Service-Token` (`DBP_SERVICE_TOKEN`, default `dev-service-token`).

Everything a UI needs must be reachable through this API; the UI never talks to the gateway or proxy
directly.

---

## 1. Teams

`Team`
```json
{ "id": "…", "name": "sales-platform", "displayName": "Sales Platform Team",
  "description": "…", "contacts": ["sales-platform@example.org"], "tags": ["domain:sales"],
  "createdAt": "…", "updatedAt": "…" }
```
* `GET /teams`, `POST /teams`, `GET /teams/{id}`, `PUT /teams/{id}`, `DELETE /teams/{id}`
* `GET /teams/{id}/summary` →
  ```json
  { "team": {…}, "applications": [Application], "ownedTables": [TableRef],
    "consumedTables": [TableRef], "producedTables": [TableRef], "datasourcesOwned": [DatasourceRef] }
  ```

## 2. Applications

`Application`
```json
{ "id": "…", "name": "orders-service", "displayName": "Orders Service", "teamId": "…",
  "kind": "SERVICE | BATCH | UI | LEGACY | TOOL", "description": "…",
  "runtime": "CLOUD_RUN | KUBERNETES | VM | OTHER",
  "identityRules": {
    "cidrs": ["10.20.0.0/16"],
    "programNames": ["orders-service", "JDBC Thin Client/orders"],
    "machinePatterns": ["orders-service-*"],
    "serviceAliases": ["orders-service"],
    "pgApplicationNames": ["orders-service"]
  },
  "tags": [], "createdAt": "…", "updatedAt": "…" }
```
* `GET /applications`, `POST /applications`, `GET /applications/{id}`, `PUT /applications/{id}`, `DELETE /applications/{id}`
* `GET /applications/{id}/summary` → `{ application, team, grants: [AccessGrant], reads: [TableRef], writes: [TableRef], calls: [RoutineRef], connections: ConnectionStats, queryStats: QueryStats }`
* API keys (the application credential used with the gateway):
  * `GET /applications/{id}/api-keys` → `[{ "id", "prefix", "label", "createdAt", "lastUsedAt", "revokedAt" }]` (never the secret)
  * `POST /applications/{id}/api-keys` `{ "label": "prod" }` → `{ "id", "prefix", "apiKey": "dbp_<prefix>_<secret>" }` — plaintext returned **once**
  * `DELETE /applications/{id}/api-keys/{keyId}` (revoke)

Identity rules are how **proxy** and **collectors** map observed connections to an application
(see `docs/telemetry-events.md`). Precedence: `serviceAliases` (service-name suffix) →
`pgApplicationNames` / `programNames` → `machinePatterns` → `cidrs`.

## 3. Physical databases

`Database`
```json
{ "id": "…", "name": "sales-oracle-prod", "engine": "ORACLE | POSTGRES | MSSQL",
  "host": "oracle.example.org", "port": 1521,
  "serviceName": "FREEPDB1",            // ORACLE service name, POSTGRES/MSSQL database name
  "credentialId": "…",                  // credential the platform itself uses (gateway pools, collectors)
  "maxPhysicalConnections": 60,
  "jdbcProperties": { "oracle.jdbc.ReadTimeout": "60000" },
  "collector": { "enabled": true, "dictionaryIntervalSeconds": 3600, "runtimeIntervalSeconds": 15,
                 "schemas": ["SALES", "INVENTORY"], "auditTrail": false },
  "description": "…", "tags": [], "createdAt": "…", "updatedAt": "…" }
```
* `GET /databases`, `POST /databases`, `GET /databases/{id}`, `PUT /databases/{id}`, `DELETE /databases/{id}`
* `POST /databases/{id}/test-connection` → `{ "ok": true, "productName": "…", "productVersion": "…", "latencyMs": 12 }`
* `POST /databases/{id}/collect` `{ "what": "DICTIONARY | RUNTIME | AUDIT" }` → `{ "started": true }` (manual trigger)
* `GET /databases/{id}/schemas` → `[{ "name": "SALES", "tableCount": 12, "routineCount": 7 }]`
* `GET /databases/{id}/collector-status` → `{ "lastDictionaryRun": "…", "lastRuntimeRun": "…", "lastError": null, "tablesSeen": 42 }`

## 4. Credentials

`Credential`
```json
{ "id": "…", "name": "sales-oracle-app-user", "username": "SALES_APP",
  "provider": "INLINE | ENV | FILE | VAULT | GCP_SECRET_MANAGER | AWS_SECRETS_MANAGER",
  "ref": "SALES_ORACLE_PASSWORD",       // env var name, file path, vault path, secret resource name; null for INLINE
  "rotatedAt": "…", "description": "…", "createdAt": "…", "updatedAt": "…" }
```
* `GET /credentials`, `POST /credentials` (`{ …, "secret": "…" }` only for INLINE; stored encrypted with `DBP_MASTER_KEY`), `GET /credentials/{id}`, `PUT /credentials/{id}`, `DELETE /credentials/{id}`
* `POST /credentials/{id}/rotate` `{ "secret": "…" }` (INLINE) or `{}` (re-read from provider) → bumps `rotatedAt` and `version`; gateways learn about it through `/internal/resolve` (`credentialVersion`) and drain old physical connections.
* Secret material is **never** returned on public endpoints.

## 5. Logical datasources

`Datasource`
```json
{ "id": "…", "name": "sales", "displayName": "Sales domain data", "ownerTeamId": "…",
  "state": "ACTIVE | MIGRATING | RETIRED",
  "currentDatabaseId": "…", "targetDatabaseId": null,
  "poolPolicy": { "mode": "TRANSACTION | SESSION", "maxConnections": 40, "minIdle": 2,
                  "connectionTimeoutMs": 10000, "idleTimeoutMs": 600000, "maxLifetimeMs": 1800000,
                  "statementTimeoutSeconds": 0, "validationQuery": null },
  "routingRules": [
    { "id": "…", "priority": 10, "applicationId": "…", "tag": null, "databaseId": "…", "readOnly": false, "enabled": true }
  ],
  "description": "…", "tags": [], "createdAt": "…", "updatedAt": "…" }
```
Resolution for a given application: first enabled routing rule (ordered by `priority` ascending)
whose `applicationId` matches, else whose `tag` matches one of the application's tags, else
`currentDatabaseId`. This is how a single domain migrates app by app from Oracle to PostgreSQL.

* `GET /datasources`, `POST /datasources`, `GET /datasources/{id}`, `PUT /datasources/{id}`, `DELETE /datasources/{id}`
* `PUT /datasources/{id}/routing-rules` (replace list), `POST /datasources/{id}/routing-rules`, `DELETE /datasources/{id}/routing-rules/{ruleId}`
* `POST /datasources/{id}/switch` `{ "databaseId": "…" }` → sets `currentDatabaseId`, records a `MigrationEvent`
* `GET /datasources/{id}/summary` → `{ datasource, ownerTeam, currentDatabase, targetDatabase, grants: [AccessGrant], consumers: [Application], pools: [PoolStats], tables: [TableRef] }`

## 6. Access grants (application ↔ datasource)

`AccessGrant`
```json
{ "id": "…", "applicationId": "…", "datasourceId": "…",
  "maxLogicalConnections": 50, "maxProxyConnections": 20,
  "poolModeOverride": null, "readOnly": false, "enabled": true,
  "note": "…", "createdAt": "…", "updatedAt": "…" }
```
* `GET /access-grants?applicationId=&datasourceId=`, `POST /access-grants`, `PUT /access-grants/{id}`, `DELETE /access-grants/{id}`

## 7. Metadata catalogue

`Table`
```json
{ "id": "…", "databaseId": "…", "schema": "SALES", "name": "CUSTOMER", "kind": "TABLE | VIEW | MATERIALIZED_VIEW",
  "ownerTeamId": "…", "ownerConfirmed": true, "ownerSource": "DECLARED | INFERRED | NONE",
  "producerApplicationId": "…",
  "rowCountEstimate": 120000, "lastDdlAt": "…", "lastSeenAt": "…", "firstSeenAt": "…",
  "migration": { "targetDatabaseId": null, "targetSchema": null, "targetName": null, "state": "NOT_PLANNED | PLANNED | IN_PROGRESS | DONE" },
  "description": "…", "tags": [], "classification": "PII | CONFIDENTIAL | INTERNAL | PUBLIC | null" }
```
`Column` `{ "id", "tableId", "name", "position", "dataType", "length", "precision", "scale", "nullable", "defaultValue", "comment", "classification" }`

`Routine`
```json
{ "id": "…", "databaseId": "…", "schema": "SALES", "name": "ORDER_PKG.PLACE_ORDER",
  "kind": "PROCEDURE | FUNCTION | PACKAGE | PACKAGE_BODY | TRIGGER | VIEW",
  "triggerTableId": null, "triggerEvent": null,
  "ownerTeamId": "…", "status": "VALID | INVALID", "lastDdlAt": "…", "lastSeenAt": "…" }
```

`Dependency` (object → object, static, from the data dictionary or declared by a human)
```json
{ "id": "…", "fromType": "ROUTINE | TABLE", "fromId": "…", "toType": "TABLE | ROUTINE", "toId": "…",
  "kind": "REFERENCES | READS | WRITES | FOREIGN_KEY | TRIGGERS | CALLS",
  "source": "DICTIONARY | RUNTIME | DECLARED", "confidence": 1.0, "firstSeenAt": "…", "lastSeenAt": "…" }
```

`Relationship` (application → object, derived from runtime telemetry or declared)
```json
{ "id": "…", "applicationId": "…", "objectType": "TABLE | ROUTINE", "objectId": "…",
  "kind": "READS | WRITES | CALLS",
  "source": "GATEWAY | PROXY_CORRELATION | COLLECTOR_SESSION | COLLECTOR_AUDIT | DECLARED",
  "queryCount": 1234, "lastSeenAt": "…", "firstSeenAt": "…", "confirmed": false,
  "viaRoutineId": null }
```
`viaRoutineId` is set when the access is indirect (application calls a routine/trigger that touches
the table). Both the direct relationship (app CALLS routine) and the expanded one (app WRITES table
via routine) are stored, so the graph can show either view.

Endpoints:
* `GET /tables?databaseId=&schema=&q=&ownerTeamId=&unowned=true&page=&size=` → paged `Table[]`
* `GET /tables/{id}`, `PUT /tables/{id}` (owner, producer, description, tags, classification, migration)
* `GET /tables/{id}/columns`, `PUT /tables/{id}/columns/{columnId}` (comment/classification)
* `GET /tables/{id}/summary` →
  ```json
  { "table": {…}, "database": {…}, "ownerTeam": {…}, "producer": Application,
    "consumers": [{ "application": {…}, "team": {…}, "kind": "READS|WRITES|CALLS", "queryCount": 1, "lastSeenAt": "…", "viaRoutine": RoutineRef }],
    "routines": [RoutineRef], "triggers": [RoutineRef], "foreignKeysOut": [TableRef], "foreignKeysIn": [TableRef],
    "views": [RoutineRef], "queryStats": QueryStats, "topQueries": [QueryStat] }
  ```
* `POST /tables/{id}/ownership` `{ "teamId": "…", "confirmed": true }`
* `POST /tables/bulk-ownership` `{ "databaseId": "…", "schema": "SALES", "teamId": "…" }` (assign owner to every table in a schema)
* `GET /routines?databaseId=&schema=&kind=&q=`; `GET /routines/{id}`; `GET /routines/{id}/summary` → `{ routine, dependencies: [Dependency with resolved names], callers: [Application], tables: [TableRef] }`
* `GET /dependencies?fromId=&toId=&kind=`; `POST /dependencies` (DECLARED); `DELETE /dependencies/{id}` (DECLARED only)
* `GET /relationships?applicationId=&objectId=&kind=&source=`; `POST /relationships` (DECLARED); `PUT /relationships/{id}` (`confirmed`); `DELETE /relationships/{id}`

## 8. Graph and impact analysis

* `GET /graph?root=<type>:<id>&depth=2&include=teams,applications,tables,routines,databases&edgeKinds=OWNS,READS,WRITES,CALLS,REFERENCES,FOREIGN_KEY,TRIGGERS,HOSTS,MIGRATES_TO,BELONGS_TO`
  `type ∈ team | application | datasource | database | table | routine`. Without `root`, returns the
  whole graph (capped by `limit`, default 500 nodes, `truncated: true` when capped).
  ```json
  { "nodes": [{ "id": "table:…", "type": "TABLE", "label": "SALES.CUSTOMER", "refId": "…",
                "attrs": { "engine": "ORACLE", "ownerTeam": "sales-platform", "queryCount": 120 } }],
    "edges": [{ "id": "…", "from": "application:…", "to": "table:…", "kind": "READS",
                "attrs": { "queryCount": 120, "lastSeenAt": "…", "source": "GATEWAY", "confirmed": false } }],
    "truncated": false }
  ```
  Node id format is `<type>:<refId>` with lowercase type.

* `GET /impact/table/{id}` and `GET /impact/column/{columnId}` →
  ```json
  { "target": { "type": "TABLE", "id": "…", "label": "SALES.CUSTOMER" },
    "owner": Team, "producer": Application,
    "directConsumers": [{ "application": {…}, "team": {…}, "kind": "READS", "queryCount": 1, "lastSeenAt": "…" }],
    "indirectConsumers": [{ "application": {…}, "team": {…}, "viaRoutine": RoutineRef, "kind": "WRITES" }],
    "routines": [RoutineRef], "triggers": [RoutineRef], "dependentViews": [RoutineRef],
    "foreignKeyDependents": [TableRef],
    "teamsAffected": [Team], "queryStats": { "count24h": 1, "count7d": 1, "lastSeenAt": "…" },
    "riskScore": 0.72, "riskFactors": ["4 consuming teams", "written by trigger", "PII"] }
  ```
  Column impact additionally lists `queriesReferencingColumn` (from normalized SQL when available).

* `GET /impact/datasource/{id}` → consumers of every table currently routed through the datasource (used before a migration switch).

## 9. Telemetry ingestion (internal)

* `POST /internal/telemetry/queries` → body `QueryEvent[]` (see `docs/telemetry-events.md`) → `202 { "accepted": n }`
* `POST /internal/telemetry/connections` → body `ConnectionEvent[]` → `202`
* `POST /internal/telemetry/pools` → body `PoolStats[]` → `202`
* `POST /internal/heartbeat` → `{ "componentType": "GATEWAY | PROXY", "componentId": "…", "version": "…", "host": "…", "startedAt": "…", "stats": {…} }` → `200 { "configVersion": 17 }`

Ingestion is idempotent on `eventId`. The control plane:
1. resolves application / datasource / database / table ids (creating *unknown* placeholder tables
   when a table is seen for the first time, flagged `discovered: true`),
2. upserts `Relationship` rows (incrementing `queryCount`, `lastSeenAt`),
3. stores aggregated `QueryStat` rows per (sqlHash, applicationId, databaseId, hour),
4. stores raw events for a bounded retention window (`DBP_TELEMETRY_RETENTION_HOURS`, default 72).

## 10. Resolution for platform components (internal)

* `POST /internal/auth/application` `{ "apiKey": "dbp_…" }` → `{ "applicationId", "name", "teamId", "teamName", "tags": [] }` or `401`.
* `GET /internal/resolve/datasource/{name}?applicationId=…` →
  ```json
  { "datasource": { "id", "name", "state" },
    "grant": { "maxLogicalConnections": 50, "readOnly": false, "poolMode": "TRANSACTION" },
    "database": { "id", "name", "engine", "host", "port", "serviceName", "jdbcUrl": "jdbc:oracle:thin:@//host:1521/FREEPDB1", "jdbcProperties": {…} },
    "credential": { "id", "username", "version": 3 },
    "poolPolicy": {…}, "configVersion": 17 }
  ```
  `403` when the application has no enabled grant; `404` when the datasource is unknown.
* `GET /internal/credentials/{id}/material` → `{ "username": "…", "secret": "…", "version": 3 }` (service token only; audited).
* `GET /internal/proxy/config?proxyId=…` →
  ```json
  { "configVersion": 17,
    "listeners": [
      { "name": "oracle-main", "engine": "ORACLE", "port": 1521,
        "routes": [ { "match": "sales", "datasourceId": "…", "databaseId": "…", "host": "oracle", "port": 1521, "serviceName": "FREEPDB1", "rewriteServiceName": true } ],
        "defaultRoute": { "host": "oracle", "port": 1521, "serviceName": null, "rewriteServiceName": false } },
      { "name": "postgres-main", "engine": "POSTGRES", "port": 5432, "routes": [ … ], "defaultRoute": { … } }
    ],
    "applications": [ { "id", "name", "teamId", "identityRules": {…} } ],
    "quotas": [ { "applicationId", "datasourceId", "maxProxyConnections": 20 } ],
    "datasourceQuotas": [ { "datasourceId", "maxProxyConnections": 200 } ] }
  ```
  `match` is compared with the logical service name (Oracle `SERVICE_NAME`/`SID`, PostgreSQL
  `database`) requested by the client; `<match>.<application-alias>` is also accepted and yields
  the application identity.
* `GET /internal/config-version` → `{ "configVersion": 17 }` (components poll this every few seconds and refetch on change).

## 11. Observability and governance

* `GET /stats/overview` →
  ```json
  { "databases": 3, "datasources": 7, "applications": 33, "teams": 9, "tables": 412, "routines": 180,
    "connections": { "proxyActive": 212, "gatewayLogical": 540, "gatewayPhysical": 61 },
    "queriesLastHour": 48211, "unownedTables": 120, "crossTeamAccesses": 44, "violations": 3,
    "componentsOnline": [{ "componentType": "GATEWAY", "componentId": "gw-1", "lastHeartbeat": "…", "healthy": true }] }
  ```
* `GET /stats/connections?groupBy=application|database|datasource|team` → `[{ "key": "orders-service", "proxy": 12, "gatewayLogical": 40, "gatewayPhysical": 6 }]`
* `GET /stats/queries/top?by=count|duration|rows&window=1h|24h|7d&databaseId=&applicationId=&limit=50` → `[QueryStat]`
  `QueryStat = { "sqlHash", "sqlNormalized", "operation", "applicationId", "applicationName", "databaseId", "tables": [TableRef], "count", "avgDurationMs", "p95DurationMs", "maxDurationMs", "rows", "errors", "lastSeenAt" }`
* `GET /stats/tables/hot?window=24h&limit=50` → `[{ "table": TableRef, "reads", "writes", "applications": 5, "teams": 3 }]`
* `GET /stats/tables/unused?days=30` → `[TableRef]`
* `GET /stats/pools` → latest `PoolStats` per gateway/datasource
* `GET /connections/live` → live proxy connections (from the last proxy heartbeat snapshot) + collector session snapshot:
  `[{ "source": "PROXY|COLLECTOR", "application", "team", "datasource", "database", "engine", "clientAddr", "program", "machine", "osUser", "dbUser", "status", "openedAt", "durationSeconds", "sqlId", "currentSql" }]`
* `GET /migration-events?datasourceId=` → `[{ "id", "datasourceId", "fromDatabaseId", "toDatabaseId", "at", "by", "note" }]`
* Governance:
  * `GET /governance/policies` → `[{ "id", "kind": "CROSS_TEAM_DIRECT_ACCESS | UNOWNED_TABLE | UNDECLARED_CONSUMER | WRITE_BY_NON_PRODUCER | DIRECT_DB_ACCESS_BYPASSING_PLATFORM", "enabled": true, "severity": "LOW|MEDIUM|HIGH" }]`, `PUT /governance/policies/{id}`
  * `GET /governance/violations?status=OPEN|ACKNOWLEDGED|RESOLVED` → `[{ "id", "policyKind", "severity", "applicationId", "teamId", "objectType", "objectId", "label", "detail", "firstSeenAt", "lastSeenAt", "status" }]`, `PUT /governance/violations/{id}` (`status`)
  * Violations are recomputed by a scheduled job (`DBP_GOVERNANCE_INTERVAL_SECONDS`, default 300) and on `POST /governance/evaluate`.

## 12. Components

* `GET /components` → online gateways / proxies from heartbeats: `[{ "componentType", "componentId", "version", "host", "startedAt", "lastHeartbeat", "healthy", "stats": {…} }]`

## 13. Import / export / seed

* `GET /export` → whole configuration (teams, applications, databases without secrets, credentials without secrets, datasources, grants, declared ownership/relationships) as JSON; `POST /import` accepts the same document (upsert by `name`).
* `POST /seed/demo` → loads the demo retail dataset used by the examples and the UI demo mode (idempotent). Enabled when `DBP_DEMO_SEED_ENABLED=true` (default `true` in the `dev` profile).

## 14. OpenAPI

The control plane serves `GET /v3/api-docs` and `GET /swagger-ui.html` (springdoc). The hand-written
contract above is authoritative where the two differ during the POC.
